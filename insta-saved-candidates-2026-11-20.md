- **FluxDown vs Mister Download Manager (your comparison request; corrected 2026-11-20)** —
  your "fluxdownload manager" is **FluxDown** (fluxdown.com, zerx-lab/FluxDown), NOT Hactor00/Flux
  which I compared first by mistake. Both cover the IDM job list (segmented HTTP + resume, browser
  capture, streaming media grab, torrents, queues, schedules, speed limits). FluxDown: dynamic
  runtime segmentation with slow-segment rescue; HTTP/FTP/BitTorrent(+web seeds)/eD2K/HLS(AES)/DASH;
  Chrome/Edge/Firefox extension shipped as zip/xpi (no store listings found on its site); native
  Linux **AppImage + .deb + Arch .pkg.tar.zst**; Windows x64/ARM64; macOS; Android/iOS apps; CLI,
  headless NAS server and a built-in **MCP server** so agents can manage downloads; RSS/webhooks/
  plugins; AGPL-3.0; ~5.8k stars; v0.6.8. MDM: fixed 8-connection splitting; HTTP + torrents +
  ffmpeg-assisted video; **store-approved** Chrome and Firefox extensions; Linux AppImage/deb/rpm/
  tar.gz (no Arch pkg); IDM-familiar UI; 86 languages; GPL-3.0; ~14k stars; v0.5.2; its "5x faster"
  claim is a loopback benchmark and the reel's real Wi-Fi race showed marginal gains. Verdict:
  FluxDown is the stronger IDM replacement for your machines (native Arch package via pacman -U,
  vendor-direct, no AUR; broader protocols; CLI/MCP fits your agent workflows); MDM wins if you
  want the IDM-style window or store-installed extensions. Both kept per your decision; neither
  is a speed miracle on real links.
- **addsumtech/slides_maker** — slides brand it "Slide-maker"; repo description matches the slide
  copy exactly, but the name differs slightly. Medium-high confidence.
